# 💼 راهنمای فروش — صدور کد لایسنس برای مشتری

> راهنمای عملیاتی فروشنده: از ثبت فاکتور تا ارسال کد فعال‌سازی به مشتری.
> ابزار صدور: [`scripts/make-license-code.mjs`](../scripts/make-license-code.mjs) · جدول طرح‌ها در [README](../README.md#-طرح‌ها-و-قیمت‌گذاری) · متن حقوقی در [LICENSE](../LICENSE)

---

## چرخه‌ی فروش در یک نگاه

```text
فهمیدن نیاز مشتری → فاکتور → صدور کد → اعتبارسنجی → ارسال امن → ثبت و پیگیری
   (چت/تلفن)      (شماره + مبلغ)  (make-license-code)   (--verify)   (ایمیل/پیام)   (آرشیو)
```

---

## ۱) فاکتور

- در فاکتور بنویسید: **طرح** (مثلاً «شش‌ماهه — half-year»)، **قیمت** (بر اساس جدول README)،
  **دارنده‌ی لایسنس** (نام کامل شرکت/سازمان — همان چیزی که در سامانه نمایش داده می‌شود) و
  **رایانامه‌ی ادمین** مشتری.
- **پیش از صدور کد، پرداخت را کامل تأیید کنید** — کد صادرشده قابل ابطال نیست؛ پس از فعال‌سازی
  هر کد فقط یک‌بار مصرف است (ضد replay با `jti`).

## ۲) صدور کد

از ریشه‌ی ریپو (همان‌جا که پوشه‌ی `keys/` با کلید خصوصی هست):

```bash
node scripts/make-license-code.mjs --plan <plan> --to "نام دارنده" --email admin@customer.ir --note "فاکتور ..." [--code-days 180] [--grouped] [--out file.txt]
```

| فلگ | کاربرد | پیش‌فرض |
|------|--------|---------|
| `--plan` | `month` \| `quarter` \| `half-year` \| `year` \| `lifetime` | `year` |
| `--to` | نام دارنده (نام شرکت/سازمان مشتری — در سامانه نمایش داده می‌شود) | — |
| `--email` | رایانامه‌ی مشتری | — |
| `--note` | یادداشت آزاد — **همیشه شماره‌ی فاکتور را اینجا بنویسید** | — |
| `--code-days` | مدت اعتبار خودِ کد برای ورود (جدا از اعتبار طرح) | `180` |
| `--grouped` | قالب گروه‌بندی‌شده برای تایپ آسان (بلوک‌های ۲۴ نویسه با جداکننده‌ی `+`) | خاموش |
| `--out` | ذخیره‌ی کد در فایل (تک‌خطی، آماده‌ی پیوست ایمیل) | — |
| `--verify <code>` | اعتبارسنجی یک کد بدون سرور | — |
| `--gen-keys` | تولید جفت‌کلید RSA (فقط بار اول / چرخش با `--force`) | — |
| `--jti` | شماره‌ی سریال دستی کد (پیش‌فرض تصادفی) | تصادفی |

### دستورهای آماده — هر طرح با قیمت

قیمت‌ها به تومان و بر اساس جدول README:

```bash
# 📅 یک‌ماهه (month) — ۴٫۹۰۰٫۰۰۰ تومان
node scripts/make-license-code.mjs --plan month --to "شرکت نمونه" --email info@company.ir --note "فاکتور ۱۴۰۵-۰۰۱"

# 📅 سه‌ماهه (quarter) — ۱۲٫۵۰۰٫۰۰۰ تومان
node scripts/make-license-code.mjs --plan quarter --to "شرکت نمونه" --email info@company.ir --note "فاکتور ۱۴۰۵-۰۰۱"

# 📅 شش‌ماهه (half-year) — ۲۲٫۵۰۰٫۰۰۰ تومان — محبوب‌ترین
node scripts/make-license-code.mjs --plan half-year --to "شرکت نمونه" --email info@company.ir --note "فاکتور ۱۴۰۵-۰۰۱"

# 📅 یک‌ساله (year) — ۳۹٫۵۰۰٫۰۰۰ تومان — به‌صرفه‌ترین طرح زمان‌دار
node scripts/make-license-code.mjs --plan year --to "شرکت نمونه" --email info@company.ir --note "فاکتور ۱۴۰۵-۰۰۱"

# ♾️ دائمی (lifetime) — ۹۹٫۰۰۰٫۰۰۰ تومان — همه‌ی به‌روزرسانی‌های 1.x رایگان
node scripts/make-license-code.mjs --plan lifetime --to "شرکت نمونه" --email info@company.ir --note "فاکتور ۱۴۰۵-۰۰۱"

# 🧪 کد آزمایشی سفارشی (trial رایگان با سقف ۲۵ تجهیز — نیازی به کد ندارد؛ فقط اگر خواستید در نوت ثبتش کنید)
node scripts/make-license-code.mjs --plan month --to "شرکت نمونه" --email info@company.ir --note "نمونه‌ی آزمایشی هدیه"
```

> ⚠️ در دستورهای بالا نام/رایانامه/شماره‌ی فاکتور را با مقادیر واقعی مشتری عوض کنید.
> خروجی استاندارد: کد در **خط چهارم** چاپ می‌شود؛ با `--out file.txt` هم در فایل ذخیره می‌شود.

## ۳) اعتبارسنجی پیش از ارسال

```bash
node scripts/make-license-code.mjs --verify "کد کپی‌شده"
```

خروجی باید `signature_ok: true` بدهد و payload طرح/دارنده/انقضا را نشان دهد —
به‌ویژه برای کدهای گروه‌بندی‌شده (`--grouped`) که جداکننده‌ی `+` دارند، امضا را حتماً چک کنید.

قبل از اولین فروش واقعی، کل چرخه را با سرور تست کنید:

```bash
node scripts/smoke-test.mjs   # BASE/ADMIN_PASS/LICENSE_CODE را تنظیم کنید
```

## ۴) ارسال امن به مشتری

- کد را **در متن پیام/ایمیل** ننویسید؛ از فایل `--out` استفاده کنید و به‌صورت پیوست
  (یا کانال امن سازمانی) بفرستید.
- در پیام به مشتری بگویید: کد را با `--grouped` می‌فرستیم که بلوک‌های ۲۴ نویسه دارد و
  با جداکننده‌ی `+` جدا می‌شود — مشتری کافی است کد را **کامل کپی** کند (فعال‌سازی آفلاین است؛
  هیچ داده‌ای بیرون نمی‌رود).
- راهنمای فعال‌سازی مشتری: README ← «فعال‌سازی با کد لایسنس» (منوی **🔑 ورود کد لایسنس** ←
  «بررسی کد» ← «🔓 فعال‌سازی»).
- **پیش از صدور، مطمئن شوید شماره فاکتور در `--note` ثبت شده** — این تنها اثر پایه در سوابق است.

## ۵) ثبت و پیگیری

- فایل کد (`--out`) را در پوشه‌ی آرشیو مشتری (بیرون از ریپو) نگه دارید — کد در DB سرورِ مشتری
  ثبت نمی‌شود؛ فقط پس از فعال‌سازی در جدول `license_activations` (jti/اثر انگشت/زمان) می‌نشیند.
- ردگیری `jti` کنار شماره‌ی فاکتور: اگر مشتری گفت «کد کار نمی‌کند»، از `--verify` خروجی بگیرید.
- **تمدید/ارتقا**: برای دوره‌ی بعد یک **کد جدید** با همان فرمول صادر کنید (کد قبلی تک‌مصرف است).
  طرح/پایان فعلی از پنل مدیریت لایسنس (PUT /api/license) نیز قابل تنظیم است — برای
  هم‌ترازی حسابداری، کد جدید را با `--note` فاکتور تمدید صادر کنید.
- **استرداد/سرقت (ابطال کد)**: اگر کد فروخته‌شده مسترد شد، یا کدِ فعال‌نشده‌ای لو رفت، مشتری
  (ادمین سامانه) می‌تواند آن را باطل کند: منوی «🔑 ورود کد لایسنس» ← بخش «⛔ ابطال کد لایسنس» ←
  ورود شناسه‌ی کد (jti) یا خودِ کد. کد باطل‌شده دیگر فعال نمی‌شود (403)؛ ابطال برگشت‌پذیر است
  (لغو ابطال). جعلی‌ستیزی نهایی همین امضای RS256 با کلید خصوصی نزد شماست — اگر کد **و** کلید
  خصوصی هر دو لو رفتند، چرخش کلید (`--gen-keys --force`) لازم است.

## 🔒 نکات امنیتی (بسیار مهم)

- **کلید خصوصی** (`keys/license_private.pem`) فقط نزد فروشنده است و در `.gitignore` است —
  **هرگز کامیت، ارسال با ایمیل/پیام‌رسان، یا توزیع نکنید.** تنها چیزی که مشتری می‌گیرد، کد JWT است.
- کلید عمومی داخل image است (`server/src/lib/license_public_key.pem`)؛ برای چرخش کلید:
  `--gen-keys --force`، جایگزینی کلید عمومی و بازنشر image (یا ENV `LICENSE_PUBLIC_KEY`).
- کد فعال‌نشده **قابل ابطال نیست** — پس هرگز پیش از تأیید پرداخت صادر نکنید؛ اگر کدی بیرون رفت،
  چرخش کلید تنها راه ابطال همه‌ی کدهاست.
- پشت `keys/` و آرشیو فایل‌های کد، دسترسی محدود نگه دارید (فقط مدیر فروش/ادمین سیستم).

## 🩺 رفع اشکال متداول

| نشانه | علت | راه‌حل |
|--------|-----|--------|
| «کد نامعتبر است» / 400 | کپی ناقص یا امضای خراب (معمولاً جداکننده‌ی `+` حذف شده یا کد جعلی) | کد را کامل کپی کنید؛ با `--verify` چک کنید |
| 409 در فعال‌سازی | کد قبلاً مصرف شده (replay) | برای مشتری کد جدید صادر کنید؛ jti در سوابق هست |
| 403 «کد باطل شده است» | کد در لیست ابطال است (استرداد/سرقت) | پس از توافق، مشتری از پنل «ابطال» آن را لغو ابطال کند یا کد جدید بدهید |
| کد وارد می‌شود ولی «منقضی» | اعتبار خودِ کد برای ورود تمام شده (`--code-days`) — نه اعتبار طرح | کد جدید با همان طرح صادر کنید |
| طرح اعمال شد ولی سقف تجهیز باقی است | مشتری بعد از فعال‌سازی سامانه را بازسازی کرده و لایسنس پاک شده | کد جدید بدهید یا از پنل مدیریت لایسنس دوباره تنظیم کنید |

> 💡 «اعتبار ورود کد» (پیش‌فرض ۱۸۰ روز) یعنی مشتری تا آن زمان فرصت دارد کد را در سامانه وارد کند؛
> «اعتبار طرح» (۱/۳/۶/۱۲ ماه یا دائمی) از لحظه‌ی **فعال‌سازی** شروع می‌شود — این دو یکی نیستند.

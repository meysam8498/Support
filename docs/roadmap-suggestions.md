# نقشه‌ی راه پیشنهادی — ارتقا، رفع نواقص و بهترین‌ها

تاریخ: 2026-10-10 · نسخه‌ی فعلی: 1.27.0 (+ تغییرات ابطال لایسنس آماده‌ی کامیت)

اولویت‌بندی بر اساس ریسک/ارزش برای یک محصول تجاری که روی سرور مشتری نصب می‌شود.

## 🔴 فوری — پیش از فروش واقعی

1. **JWT secret پیش‌فرض** — `'dev-secret-change-me'` در `server/src/lib/auth.ts`؛ اگر مشتری بدون ENV بالا بیاورد جعل توکن ممکن است.
   - پیشنهاد: secret تصادفی خودکار + هشدار در لاگ؛ در حالت `LICENSE_ENFORCE=1` بدون secret قوی اصلاً بالا نیاید.
2. **CORS باز کامل** — `cors()` بدون گزینه در `server/src/index.ts`؛ برای نصب مشتری origin را محدود کن (پیش‌فرض: همان هاست خود سرور).
3. **helmet + express-rate-limit** — مخصوصاً روی `/api/auth/login` و `/api/license/*`؛ الان هیچ‌کدام نیست.
4. **پکیج `xlsx`** — CVE بدون فیکس (prototype pollution / ReDoS)؛ ارزیابی جایگزین (`exceljs`) یا پذیرش ریسک با محدودکردن ورودی import.
5. **audit پکیج‌ها** — ۲۰ مورد (۹ high، ۲ critical)؛ تقریباً همه با `npm audit fix` بدون breaking:
   - Critical قابل فیکس: proxy-addr، shell-quote، fast-glob، source-map-js
   - High قابل فیکس: vite، tailwindcss (+ braces/chokidar/micromatch/nanoid)

## 🟠 کوتاه‌مدت — کیفیت محصول

6. **تست خودکار واقعی** — فقط smoke داریم؛ چرخه‌های حیاتی (فعال‌سازی لایسنس، ابطال/لغو، auth، سقف تجهیزات) را با vitest + sqlite in-memory تست رسمی کن.
7. **ایمیل خودکار چرخه‌ی فروش** — در صدور/ابطال، پیش‌نویس ایمیل به مشتری ساخته شود (الان قالب دستی در پنل است).
8. **`.env.example` کامل** — همه‌ی متغیرها مستند: JWT_SECRET، JWT_EXPIRES_HOURS، LICENSE_ENFORCE، SUPPORT_LOG_TOKEN، DB_PATH، BACKUP_DIR، ...
9. **بکاپ زمان‌بندی‌شده** — کتابخانه‌ی بکاپ هست؛ یک زمان‌بند ساده (نود cron) اضافه شود + نگهداری N نسخه‌ی آخر.
10. **چرخش کلید امضای لایسنس** — اگر `keys/license_private.pem` لو رفت، بتوان بدون باطل‌کردن همه‌ی کدها کلید را عوض کرد (key id در کد).

## 🟡 متوسط — رشد محصول

11. **audit log عمومی** — جدول `audit_log` برای «چه‌کسی، کِی، چه چیزی را تغییر داد» در عملیات مهم (کاربر، لایسنس، تجهیز، حذف قطعه).
12. **دسترسی نقش‌ها پیکربندی‌شونده** — نقش‌ها الان ثابت در کد است؛ نگاشت نقش→دسترسی در DB/تنظیمات تا مشتری بدون کدنویسی تنظیم کند.
13. **تور روز اول** — راهنمای تعاملی برای مشتری جدید (چند مرحله‌ی ساده: ساخت پروژه → تجهیز → قطعه).
14. **اپ موبایل/بارکدخوان** — مسیر `/api/serial-import` mobile آماده است؛ یک PWA سبک روی آن بساز.

## 🟢 بلندمدت / اختیاری

- **SSO/OIDC** برای سازمان‌های بزرگ.
- **Multi-tenancy** — چند مشتری روی یک نصب (فقط اگر مدل فروش تغییر کند).
- **داشبورد تحلیلی پیشرفته** — روند خرابی per-model، پیش‌بینی خرید قطعه.

## 🔁 چرخه‌ی نگهداری مداوم

- `npm audit fix` ماهانه + فعال‌کردن Dependabot روی GitHub.
- پیش از هر ریلیز: `npm run build && npm run test:smoke:full` (۳۸ چک).

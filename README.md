## ✨ امکانات

### مدیریت تجهیزات
- **ثبت جامع دستگاه و قطعات** با تمام فیلدها (نوع، برند، مدل، سریال، پارت‌نامبر، مشخصات فنی، و …)
- **تاریخ خروج از انبار** و **تاریخ تحویل به مشتری** (ورودی شمسی با تقویم پاپ‌آپ، ذخیره‌ی شمسی+میلادی)
- **وضعیت دستگاه:** فعال | معیوب | در حال تعویض | تعویض‌شده
- **علت تعویض:** سخت‌افزار / نرم‌افزار / سایر + شرح توضیحات

### گارانتی
- **مدت گارانتی** (ماه) + **تاریخ شروع گارانتی** → محاسبه‌ی خودکار پایان گارانتی
- **درخواست‌های گارانتی:** در انتظار | تأیید | رد | انجام‌شده
- **تعویض قطعه تحت گارانتی:** جریان مرحله‌ای (انتخاب پروژه ← دستگاه ← قطعه‌ی خراب ← قطعه‌ی جدید)
- **ردیابی زنجیره‌ای:** مسیر کامل قطعه از فروش تا تمام تعویض‌ها

### تأمین قطعات
- **منبع تأمین:** داخلی / خارجی
- **تاریخ خرید** + **مدت گارانتی تأمین‌کننده** + یادداشت

### گزارش‌ها و داشبورد
- کارت‌های آماری (تعداد تجهیزات، قطعات، تعویض‌ها، پروژه‌ها)
- آخرین تعویض‌های گارانتی + لیست پروژه‌ها
- پرخرابی‌ترین قطعات، خرابی بر اساس مشتری/دلیل، نیاز خدمات به تفکیک نوع
- نمای مشتری: تجهیزات، قطعات و سابقه‌ی خدمات یک پروژه

### مدیریت لیست‌ها
- کارشناسان فروش/فنی، برندها، انواع و مدل‌های دستگاه، پروژه‌ها، دلایل خرابی

### احراز هویت و نقش‌ها
- **نقش‌ها:** مدیر (Admin) با دسترسی کامل CRUD | کاربر (User) فقط مشاهده
- **ورود با نام کاربری/رمز عبور** + توکن JWT
- مدیریت کاربران (افزودن، ویرایش، فعال/غیرفعال، بازنشانی رمز) — فقط مدیر

### رابط کاربری
- **تم دارک/لات** با دکمه‌ی تغییر تم
- **تقویم شمسی پاپ‌آپ** (jalaali-js) با ناوبری ماه/سال، کلید «امروز»، کلیک بیرون برای بستن
- **فارسی RTL** — کاملاً راست‌به‌چپ
- **واکنش‌گرا (Responsive)** — سازگار با دسکتاپ و موبایل

## 🐳 اجرا با Docker (توصیه‌شده)

کل سامانه (API + فرانت‌اند) در **یک کانتینر** روی پورت 4000 سرو می‌شود.

### ۱) تنظیم متغیرهای محیطی

```bash
cp .env.example .env
# سپس JWT_SECRET و رمزهای کاربران را در .env ویرایش کنید
```

### ۲) ساخت و اجرا

```bash
docker compose up -d --build
```

سپس مرورگر را باز کنید: **http://localhost:4000**

**حساب‌های پیش‌فرض:**
| نقش | نام کاربری | رمز عبور |
|------|-----------|----------|
| مدیر (Admin) | `admin` | `admin123` |
| کاربر (User) | `user` | `user123` |

### ۳) بازسازی کامل دیتابیس

```bash
docker compose down -v        # حذف کانتینر و volume
docker compose up -d --build  # بازسازی با seed اولیه
```

### ۴) بررسی سلامت

```bash
curl http://localhost:4000/api/health
```

## 🔑 ساختار پروژه

```
Support/
├─ server/                     # بک‌اند: Node.js + Express + TypeScript
│  └─ src/
│     ├─ db/                   # اسکیمای SQLite، راه‌انداز و seed
│     ├─ routes/               # API: auth, devices, parts, warranty, lists,
│     │                        #      warrantyRequests, procurement, users, dashboard, reports
│     ├─ middleware/            # احراز هویت و کنترل نقش (requireRole)
│     └─ lib/                  # تبدیل تاریخ شمسی/میلادی، رمز و توکن
├─ client/                     # فرانت‌اند: React 18 + Vite + TypeScript + Tailwind CSS
│  └─ src/
│     ├─ pages/                # صفحه‌ها (داشبورد، تجهیزات، قطعات، گارانتی، گزارش‌ها، لیست‌ها، کاربران)
│     ├─ components/           # JalaliDatePicker, StatusBadge, Modal, Layout, SelectField
│     ├─ context/              # ThemeContext (دارک/لات), AuthContext (کاربر + نقش)
│     ├─ api/api.ts            # کلاینت API با انواع TypeScript
│     └─ i18n/fa.ts            # برچسب‌های فارسی
├─ Dockerfile                  # Multi-stage build (builder + runtime)
├─ docker-compose.yml
├─ .env.example
└─ README.md
```

### مدل داده (خلاصه)

- **users** — نقش (`admin` | `user`) + ایمیل + فعال/غیرفعال
- **devices** — تجهیزات با وضعیت، تاریخ انبار/تحویل، گارانتی، علت تعویض
- **parts** — قطعات با زنجیره‌ی جایگزینی (`replaces_part_id`)
- **warranty_replacements** — تاریخچه‌ی تعویض
- **warranty_requests** — درخواست‌های گارانتی
- **procurement** — تأمین قطعات (داخلی/خارجی)

هر تاریخ هم شمسی (`*_jalali`) و هم میلادی (`*_gregorian`) ذخیره می‌شود.

## 🛡️ امنیت

- رمزهای عبور با `bcrypt` هش می‌شوند
- نشست با توکن JWT و انقضای زمانی
- middleware `requireRole('admin')` برای محدودسازی نوشتن
- اعتبارسنجی ورودی‌ها با `zod`
- فایل دیتابیس و `.env` در گیت نادیده گرفته می‌شوند
